## 修复 Cloudflare Workers 构建失败（wrangler preview 缺 previews 块）

- 现象：Git 连接的 Workers Builds 执行 `npx wrangler preview`（wrangler 4.149.0）报错
  `Your Wrangler configuration is missing a previews block`，构建失败。
- 原因：Cloudflare 新版 Worker Previews（wrangler ≥ 4.135.0）要求 wrangler 配置里必须有
  `previews` 块（可以为空）；新建 Worker 的预览分支默认部署命令就是 `npx wrangler preview`。
- 修复：在 `wrangler.toml` 末尾追加空的 `[previews]` 表（附中文注释说明）。
  `assets` / `compatibility_date` / `compatibility_flags` 必须留在顶层，不能放进 previews。
- 已用 tomllib 校验配置解析正常：`{name, compatibility_date, assets, previews:{}}`。
- 遗留观察（未处理）：`assets = { directory = "." }` 会把仓库根目录整体作为静态资源，
  `game.zip`、`kidboard-pages.zip`、`README.md`、`deploy.sh`、`docs/`、`scripts/` 都会公开可访问
  （以 `.` 开头的目录默认被忽略，所以 .deploy/.shots/.workbuddy 不受影响）。
  如需收敛可加 `.assetsignore`。
- 项目存在两条部署链路：`deploy.sh`（Cloudflare Pages 项目 kidboard）与 wrangler.toml
  （Worker kidboard + Static Assets）。生产分支部署命令应为 `npx wrangler deploy`。

## 修复「改了代码浏览器刷新不更新」（HTTP 强缓存截胡 Service Worker）

- 根因（两因素叠加，缺一不可）：
  1. `_headers` 给 `/css/*`、`/js/*` 写了 `max-age=86400` 强缓存一天。
     Cloudflare 对静态资源的默认策略本就是 `public, max-age=0, must-revalidate` + ETag，
     这里等于主动把安全策略改成了危险策略。
  2. `index.html` 里的 `?v=` 版本参数从 commit `ddb1b6b` 之后就没再同步 bump
     （css 停在 v55、js 停在 v56，而 sw.js 的 `CACHE` 已涨到 v60）。
     URL 不变 → 浏览器 24h 内直接用本地旧副本；且 SW 里的 `cache.add()` / `fetch()`
     同样会命中这个 HTTP 缓存，导致**新 SW 也把旧文件装进新缓存** ——
     所以「bump 版本号」这套机制被 HTTP 缓存整个架空了。
- 修复内容：
  - `_headers`：`/css/*`、`/js/*` → `public, max-age=0, must-revalidate`（走 ETag 304）。
  - `sw.js`：`CACHE` v60 → v61；install 用 `fetch(u, {cache:'reload'})` + `c.put`
    替代 `c.add`；运行期（后台更新 / 未命中分支 / 导航）统一 `cache:'no-cache'`。
  - `index.html`：`?v=` 全部统一到 v61（36 处），作废已中毒的浏览器缓存条目。
  - 新增 `scripts/bump_version.py`：一条命令同步 sw.js 的 CACHE 与页面的 `?v=`
    （`--show` 查看、`--to N` 指定、默认 +1）。
- 部署链路：Cloudflare Git 构建 → 推到 `origin/main` 与 `origin/dev` 即自动部署。
- 项目约定：**发布时必须让 sw.js 的 CACHE 与 index.html 的 `?v=` 一起变**，
  直接用 `python3 scripts/bump_version.py` 完成，不要再手改其中一个。
